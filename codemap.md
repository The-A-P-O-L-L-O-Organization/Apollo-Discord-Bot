# Repository Atlas: Apollo-Discord-Bot

## Responsibility
Strict TypeScript ESM Discord bot on discord.js v14, Node 22+ (CI and production Node 26), pnpm only. Provides moderation, automod, tickets, integrations, interlink bot-to-bot RPC, utility, and admin features through 7 first-party plugins (admin, automod, integrations, interlink, moderation, tickets, utility) with sandboxed worker support, BullMQ queue execution, Redis EventBus, Knex persistence (PostgreSQL via pg or SQLite via better-sqlite3), OpenTelemetry plus Prometheus plus pino observability, and i18next localization across 6 locales with en-US canonical.

## Design
- Language and runtime: strict TypeScript ESM with `.js` suffix relative imports, `import type` for types, tsx for dev (`pnpm dev`, `pnpm start` on `src/index.ts`), tsc build to `dist/`, production runs `node dist/index.js`.
- Entry points: `src/index.ts` with `RUN_MODE=gateway|worker`, `src/shard.ts` sharding entry, `src/worker.ts` queue worker entry, `bin/apollo.ts` admin CLI (`pnpm apollo`), `scripts/deploy-commands.ts` slash-command registration (requires `DISCORD_TOKEN` plus `CLIENT_ID`, guild-scoped when `GUILD_ID` is set, otherwise global).
- Persistence and queue: Knex with pg or better-sqlite3 selected by `config.db`, migrations in `src/db/migrations/*.cjs`, BullMQ plus ioredis with Redis required for queue, EventBus, schedulers, spam counters, and interlink state.
- Contracts: buf-managed `protos/interlink/` and `protos/nsfw/` generating `src/generated/` (never hand-edited), `plugin-manifest.json` pinned hashes regenerated by `pnpm manifest`, ESLint flat config over `src/**/*.ts`, Vitest over `tests/**/*.test.ts` with `tests/setup.ts` and `tests/mocks/discord.ts` (about 162 test files).
- Environment: `.env` required with `DISCORD_TOKEN`, `CLIENT_ID`, `OWNER_IDS`, `OPERATOR_AGREEMENT=true`, `OPERATOR_CONTACT`, `ENCRYPTION_KEY` (comma-separated rotation, active first). No `src/handlers/`, no committed `src/data/`, no `k8s/` directory.
- Operations: 8 GitHub workflows (ci, deploy, docker, integration-tests, release, security, semgrep, setup), Dockerfiles plus `docker-compose.yml` (single bot profile and multi profile with postgres plus redis), docs in `docs/architecture/`, `docs/runbooks/`, `docs/i18n.md`, `docs/discordjs-v15-audit.md`, legal in `legal/` (TOS, PRIVACY, LEGAL).

## Flow
1. Developer runs `pnpm install`, copies `.env.example` to `.env`, runs `pnpm migrate` and `pnpm deploy-commands`, then `pnpm dev` (tsx watch on `src/index.ts`) or `pnpm build` followed by `node dist/index.js`.
2. Gateway role (`RUN_MODE=gateway`) acquires Redis leader lock in `src/gateway/leader.ts`, connects to Discord, loads plugins via `PluginManager`, and runs schedulers under `withLock`.
3. Discord interactions are serialized by `src/queue/serializeInteraction.ts`, enqueued in BullMQ via `src/queue/queue.ts`, and processed by `src/queue/jobs/processCommand.ts` in worker role (`RUN_MODE=worker` or `src/worker.ts`).
4. Cross-pod coordination flows over Redis EventBus (`plugin.action` names), Unix socket RPC (`/tmp/apollo.sock` or `APOLLO_SOCKET_PATH`), and optional interlink HTTP relay in `services/interlink/`.
5. Verification flows through `pnpm lint`, `pnpm typecheck`, `pnpm test` or `pnpm vitest run <path>`, `pnpm lint:locales`, `pnpm proto:lint` plus `pnpm proto:breaking`, and `pnpm manifest` after plugin source changes.

## Integration
- Internal map: `bin/` CLI entry, `scripts/` maintenance scripts, `src/` application root, `src/cli/` CLI orchestration and socket IPC, `src/config/` env singleton, `src/core/` plugin lifecycle plus EventBus plus worker sandbox, `src/db/` Knex adapters and migrations, `src/gateway/` leader election, `src/plugins/` 7 first-party plugins with `commands/`, `events/`, optional `cli/`, `src/queue/` BullMQ creation plus serialization plus metrics, `src/utils/` shared helpers (db, logger, lock, health, schedulers, safeFetch), `src/i18n/` locales by plugin namespace, `src/observability/` traces and metrics, `src/generated/` buf output, `services/interlink/` Go relay, `tests/` Vitest suite with fixtures and mocks.
- External systems: Discord API via discord.js v14, Redis via ioredis and BullMQ, PostgreSQL or SQLite via Knex, Unix domain sockets for gateway-worker RPC, HTTP for interlink and GitHub webhooks (HMAC verified), OpenTelemetry collector and Prometheus for telemetry.
- Per-folder detail lives in sibling `codemap.md` files under `src/`, `bin/`, `scripts/`, and `tests/` plus deeper `src/*/codemap.md` maps.
